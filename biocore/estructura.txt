connection.py — El puente con la base de datos
Imagínalo como el cable de conexión entre tu código Python y PostgreSQL. Hace 3 cosas:
Lee la dirección de la base de datos desde el archivo .env
Crea el motor (engine) que sabe cómo hablar con PostgreSQL
Maneja sesiones — cada vez que necesites leer o guardar algo en la BD, este archivo abre y cierra la conexión correctamente
Sin este archivo, tu código no sabría dónde está la base de datos ni cómo conectarse.


.env — Las credenciales secretas
Es como un archivo de configuración privado donde guardas datos sensibles que no deben ir en el código:
La dirección de la base de datos
Usuario y contraseña de PostgreSQL
Claves secretas del sistema
La ventaja es que si algún día cambias la contraseña o mueves la base de datos a otro servidor, solo cambias el .env sin tocar el código. Además este archivo nunca se sube a GitHub para que nadie robe tus credenciales.

docker-compose.yml
¿Qué hace este archivo?
Imagínalo como una receta que le dice a Docker:

Descarga PostgreSQL versión 15
Crea una base de datos llamada biocore_db
Con usuario biocore y contraseña biocore123
Expón el puerto 5432 para que Python pueda conectarse
Guarda los datos en un volumen para que no se pierdan si reinicias

backend/main.py
Es el punto de entrada del sistema — el primero que se ejecuta cuando arrancas el servidor. Hace 3 cosas:

Conecta con PostgreSQL y crea las tablas automáticamente si no existen
Inicia FastAPI como servidor web
Expone una ruta / para verificar que todo funciona


La primera pantalla (127.0.0.1:8000) es la API respondiendo — confirma que el servidor está corriendo.
La segunda pantalla (127.0.0.1:8000/docs) es Swagger UI — es una herramienta que FastAPI genera automáticamente. Es como un panel de control de tu API donde puedes:
Ver todos los endpoints del sistema
Probarlos directamente desde el navegador sin escribir código
Ver qué datos recibe y qué datos devuelve cada uno
Por ahora solo tienes el endpoint / de inicio. Conforme vayamos agregando funciones como registrar usuarios, marcar asistencia, etc., irán apareciendo aquí automáticamente.

backend/biometric/detector.py
¿Qué hace este archivo?
Tiene 3 funciones — el corazón del sistema biométrico:
capturar_fotos() — abre la cámara y toma 5 fotos automáticamente, descartando las que no tengan rostro visible
generar_encoding() — analiza las fotos y genera un vector numérico único del rostro, como una huella digital digital. Promedia los 5 encodings para mayor precisión
verificar_rostro() — cuando alguien quiere marcar asistencia, captura su rostro y lo compara matemáticamente con el encoding guardado. Si la similitud es mayor al 60% es la misma persona

backend/api/routes.py
¿Qué hace este archivo?
Tiene 6 endpoints — son las puertas de entrada al sistema:
GET /usuarios — lista todos los empleados registrados
POST /usuarios/registrar — registra un empleado nuevo y captura su rostro
POST /marcaje/verificar — identifica quién está frente a la cámara
POST /marcaje/registrar — guarda el marcaje con su tipo y justificación
POST /marcaje/audio — guarda la nota de voz del marcaje especial
GET /admin/marcajes — panel de RRHH con filtros por fecha y empleado
PUT /admin/justificacion — RRHH aprueba o rechaza una justificación
